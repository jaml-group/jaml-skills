# Theme authoring

Use this to create a new theme, add swatches, or restyle an existing theme's visual identity. Restructuring an existing theme's token or recipe contracts follows [Theme refactor](refactor-theme.md).

A theme is three owners working together: `sys` tokens hold every theme/swatch decision, a few `cmpt` tokens tune supported component seams, and one unwrapped stylesheet holds recipes. Lumi makes one set of decisions serve both light and dark mode. Read [Theme](../references/Theme/theme.md) for the model, then follow these steps in order.

1. **Translate the identity into owners.** List the theme's signature treatments, such as gloss gradients, bevels, flat strokes, hard shadows, translucency or typography, and assign each to an owner: a `sys` value, a [supported `cmpt` seam](../references/Theme/tokens.md#cmpt), a stylesheet recipe on an [anatomy hook](../references/Theme/anatomy.md), a built-in style plugin, or a [decorative layer](../references/Theme/stylesheets.md#decorative-layers) for brackets, gloss, patterns and scanlines. Choose the swatch set (accent plus ordered color set per swatch) and the [mode strategy](../references/Theme/color.md#lumi-levels-and-mode-strategy). Done when every treatment has an owner and a hook, and any treatment without a hook is recorded as a limitation.
2. **Create the module skeleton.** Follow [Structure](../references/Theme/structure.md#minimal-theme-module): a default-exported option, the complete stylesheet registered under `document.header`, a complete `sys` built by merging `sysLit`, and a minimal `cmpt`. Build it into the served theme directory following [Build And Discovery](../references/Theme/structure.md#build-and-discovery), restarting any running watch build so it discovers the new folder. Done when the theme is selectable at runtime, applies without console errors, and switching to another theme removes all of its recipes.
3. **Author `sys`.** Set typography (`typography.fontFamily.ui` drives the page font), space, radius, width, shadow and text-shadow scales, motion and timing. Build `sys.color` with adaptive builders and lumi levels from the [baseline level map](../references/Theme/color.md#lumi-levels-and-mode-strategy), keeping every family's [semantic job](../references/Theme/color.md#token-usage-guide). Put true mode exceptions in one sparse `light` or `dark` branch. Done when the [Tokens](../references/Theme/tokens.md) contract holds: the registered `sys` is complete, filled-state backgrounds are opaque, and each mode branch path exists in the root.
4. **Tune component seams.** Override only the `cmpt` values whose component your identity changes, carrying `sys` token references. Done when each override is a listed seam and no theme-private component token was invented.
5. **Write the recipes.** Write `styles/index.scss` with literal framework selectors from [Anatomy](../references/Theme/anatomy.md) and [Stylesheets](../references/Theme/stylesheets.md), consuming `var(--jam-…)` tokens. For elements that opt into `variant: 'standard'`, define the [standard role recipes](../references/Theme/authoring.md#standard-role-recipes) in `index.mjs` `styles`. Map recipes use ECharts plugins for region fills and name ink. Cover the [theme-complete checklist](../references/Theme/authoring.md#theme-complete-checklist) area by area. Done when every checklist area has an intentional recipe or deliberately inherits the native one, and the stylesheet contains no theme wrapper or project class.
6. **Register swatches.** The first swatch carries the complete token buckets; later swatches inherit and override per [Swatch Inheritance](../references/Theme/tokens.md#swatch-inheritance). Give each swatch a distinct accent and color set. Done when every swatch applies in both modes and selecting it changes only what it declares.
7. **Verify on a preview page.** Use the host project's theme preview page when it has one; otherwise compose one JAML page that exercises the checklist: app shell, surfaces, every button type and its disabled and checked states, button groups, checkbox and radio options, inputs including text area, select and date, switch, tags and badges, table, tree, steps, popup, modal, tooltip, notifications, charts, a standard map, and controls on accent parents. Switch theme, swatch and mode with the native theme panel; theme changes confirm and reload, while swatch and mode apply in place. For scripted checks without saving a preference, `jam.setTheme(name)`, `jam.Theme.currTheme.switchSwatch(document.body, swatchName)` and `jam.setDarkMode(true | false)` apply directly (`setTheme` keeps a saved accent or color set, so call `switchSwatch` after it to see the swatch's own colors); they still record the swatch in the page's saved preferences, so use a disposable browser session or reset the saved theme afterwards. Before measuring, await `jam.themeReady`, scroll lazily rendered sections into view and let entry animations settle; tooltips appear on hover only under an element that installs `Plugins.popup.tip()`. Check each swatch in light and dark mode, hover, pressed, keyboard focus and disabled states, contrast of text on every fill, state indicators that stay distinguishable from their other states (toggle each control and compare: checked, mixed and selected marks against their box, which [`checkbox.markColor`](../references/Theme/tokens.md) paints; a switch on, off and disabled; a checked button against its unchecked twin; the selected sort arrow against idle arrows), text centered vertically in controls with the font that actually resolves, and a larger root font size. Done when each area has been inspected in both modes with no unowned literal colors, and every finding is fixed or recorded with its reason.

For tables, maps, trees, adaptive colors and charts, follow [Verify native recipes](../references/Theme/authoring.md#verify-native-recipes) on the live candidate.

Report the swatches and modes inspected, findings fixed, recorded limitations, and any anatomy hook the identity needed but the framework does not expose.
