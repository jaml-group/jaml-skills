# Compose / Build

For a new app or substantial capability, start from [Design](design.md) and the selected scenario in [Building a JAML UI](../references/building-ui.md). For a small change, inspect the local design and compare only the affected capability. In an AGUI host, load [AGUI](agui.md) first; it specializes output format, isolation and response admission.

## Steps

1. **Select the owner.** Follow the [composition order](../references/JAML/purpose-and-composition.md#decide-what-the-object-means). Go straight to the guide of a known capability whose purpose and parts fit. Read the matching [chooser topic](../references/choosing-native-capabilities.md) when a choice is still open.
2. **Read its contract.** Find style and plugin guides through the [style index](../references/Styles/index.md) or [plugin index](../references/Plugins/index.md), and read element or extension guides directly. Keep the entry's arguments, defaults, prerequisites, state and persistence ownership, cleanup and limitations together with its shared family context. A forwarding contract needs its named owner's documentation before you supply a field.
3. **Wire state.** Name the state owner, publisher and consumers. Prefer shared-state bindings for shared state; direct handlers stay valid for direct commands. Keep data, caller props and instance-owned state distinct.
4. **Carry the interaction.** Preserve the design's trigger anchor, pending and failure behavior and return path. Confirm that a helper's default lifetime fits that choice, and record the concrete gap and revised owner if a requirement changes it.
5. **Arrange and present.** Reuse native parts and group distinct responsibilities. For an action the host owns, [try its native `extra` slot first and check the accessibility tree](../references/JAML/purpose-and-composition.md#choose-the-owner-before-the-slot) before adding a wrapper or sibling. Apply the selected roles, theme tokens and registered business colors, and place each declaration by [style ownership](../references/Styles/styles.md#style-ownership-and-composition). Keep adapter and pixel-contract justifications with their owner.
6. **Integrate external surfaces.** Use a bounded adapter after checking native alternatives. Preserve keyboard, accessibility, safe text rendering and cleanup.
7. **Emit the result.** Prefer a bare JSON JAML object for simple declarative output, and JavaScript builders with `export default` when composition requires them. Use `jaml()` or `jam.render()` for deliberate runtime mounting. Follow the [application-root convention](../references/JAML/component.md#standalone-application-root) for a standalone full-page app and the [explicit host boundary](../references/JAML/component.md#embedded-application-hosts) for an embedded one. Galleries keep complete legible examples, with large or shared datasets loaded through documented data contracts.
8. **Validate.** Follow [Validate](validate.md). Correct real errors, and keep valid code when a diagnostic is an evidenced analyzer limitation.

A virtualized table can use `Styles.props({ contain: 'size' })` when its layout supplies a height, such as in a bounded grid or flex region or a sized card. Size containment removes the table’s intrinsic size contribution on both axes. The table can collapse if the layout leaves its height to its contents, even with fixed-height rows.

Done: requested behavior is implemented, selected capabilities and extensions have clear ownership, application theme conventions are applied, and verification results separate static from live evidence. Reusable additions have a concise contract and an example or meaningful test.
