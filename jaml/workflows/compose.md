# Compose / Build

For a new app or substantial capability, follow [Design](design.md) and the selected scenario in [Building a JAML UI](../references/building-ui.md) first. For a small change, inspect the local design and perform only the relevant capability comparison.

For interactive assistant views in jam-dsh, load the [host AGUI contract](jam-dsh-agui.md) first; it specializes the output format, isolation and response admission below.

1. For a known capability, retrieve its current exact contract directly; for an ambiguous operation, read only its relevant chooser topic before selecting contracts. Read the selected family guide from the [style index](../references/Styles/index.md) or [plugin index](../references/Plugins/index.md); read the owning guide directly for elements and extensions. Keep prerequisites, target/input shape, defaults, state/persistence ownership, cleanup and limitations; expand related sections when they affect the change. Keep the complete argument contract with its shared family context even when focusing on one field. Consult documented editor hints when needed; forwarding contracts require their named owner before supplying fields whose behavior is not described. Explain and Maintain are conditional routes, not prerequisites for a small edit. When custom element data is needed, consult [declarative props](../references/JAML/jaml-format.md#props), including member collisions and bridge readiness; keep hooks for actual lifecycle work.
2. Name the state owner, publisher and consumers. Prefer shared-state bindings over unnecessary sibling commands; direct handlers remain valid. For private fetching, shared `data` ownership or same-query refresh, retrieve the relevant [state/data section](../references/JAML/state-and-data.md). Wire state with documented binders and lifecycle; consult [Binders](../references/JAML/binder.md) and [Components](../references/JAML/component.md) for builder/CC/usage contracts. Consult [parameter suffixes](../references/JAML/jaml-format.md#param-suffixes--keysuffix) before adding a processor. Keep data, caller props and instance-owned state distinct; for a CC editing a caller record, use the [single-record alias example](../references/JAML/component.md#one-caller-owned-record-per-cc-instance). For caption/slot changes, consult [named-slot lifecycle](../references/JAM-UI/JAM-UI.md#named-slot-lifecycle) and reuse its events with an initial read; verify the uncovered requirement before adding a `MutationObserver`.
   For input-driven business actions, read [value notifications versus explicit actions](../references/JAM-UI/JAM-UI.md#value-changes-and-explicit-actions); programmatic value updates can invoke `onchange`.
3. Apply the selected roles, theme tokens and registered business colors. Choose the owner and scope of each local declaration, shared recipe or repeated composition using [style ownership and composition](../references/Styles/styles.md#style-ownership-and-composition). Keep bounded adapter and pixel-contract justifications with their owner. For theme settings, load [theme-panel readiness](../references/JAML/component.md#theme-panel-composition-and-readiness); for reusable effects, load [mount and shared application lifetime](../references/Styles/styles.md#mount-and-shared-application-lifetime).
4. Integrate external surfaces through a bounded adapter when needed. Preserve keyboard, accessibility, safe text rendering and cleanup requirements; verify native alternatives before declaring a gap.
5. Prefer a bare JSON JAML object for simple declarative output; use JavaScript builders when composition requires them and prefer `export default`. Use `jaml()` or `jam.render()` for deliberate runtime mounting. For standalone full-page apps, follow the [application-root convention](../references/JAML/component.md#standalone-application-root); for embedded apps, preserve the [explicit host boundary](../references/JAML/component.md#embedded-application-hosts).
6. For galleries, retain complete legible examples. Keep small data inline, load large/shared datasets through documented data contracts, and extract real repetition without hiding every example behind a generic registry.
7. Follow [Validate](validate.md). Correct real errors; retain valid code when a diagnostic is an evidenced analyzer limitation.

When implementation exposes a meaningful reusable addition, follow [Upstream candidates](upstream-candidates.md) and retain its recommendation and approval status in the existing report or final handoff.

Done: requested behavior is implemented, selected capabilities and extensions have clear ownership, application theme conventions are applied, and verification results distinguish static from live evidence. Reusable additions have a concise contract and an example or meaningful test.
