# Compose / Build

For a new app or substantial capability, follow [Design](design.md) and the selected scenario in [Building a JAML UI](../references/building-ui.md) first. For a small change, inspect the local design and perform only the relevant capability comparison.

1. For a known capability, retrieve its current exact contract directly; for an ambiguous operation, read only its relevant chooser topic before selecting contracts. Use `scripts/catalog.mjs compose` for styles/plugins and `sections`/`read` for the selected element or extension’s curated contract. Keep prerequisites, target/input shape, defaults, state/persistence ownership, cleanup and limitations; expand related sections when they affect the change. `--args` retains every argument. Use `show` for editor hints; open profiles require their named owner before supplying forwarded fields. Explain and Maintain are conditional routes, not prerequisites for a small edit. When custom element data is needed, consult [declarative props](../references/JAML/jaml-format.md#props), including member collisions and bridge readiness; keep hooks for actual lifecycle work.
2. Wire state with documented binders and lifecycle; consult [Binders](../references/JAML/binder.md) and [Components](../references/JAML/component.md) for builder/CC/usage contracts. Consult [parameter suffixes](../references/JAML/jaml-format.md#param-suffixes--keysuffix) before adding a processor. Keep data, caller props and instance-owned state distinct. For caption/slot changes, consult [named-slot lifecycle](../references/JAM-UI/JAM-UI.md#named-slot-lifecycle) and reuse its events with an initial read; verify the uncovered requirement before adding a `MutationObserver`.
3. Apply the selected roles, theme tokens and registered business colors. Choose the owner and scope of each local declaration, shared recipe or repeated composition using [style ownership and composition](../references/Styles/styles.md#style-ownership-and-composition). Keep bounded adapter and pixel-contract justifications with their owner.
4. Integrate external surfaces through a bounded adapter when needed. Preserve keyboard, accessibility, safe text rendering and cleanup requirements; verify native alternatives before declaring a gap.
5. Prefer a bare JSON JAML object for simple declarative output; use JavaScript builders when composition requires them and prefer `export default`. Use `jaml()` or `jam.render()` for deliberate runtime mounting. For standalone full-page apps, follow the [application-root convention](../references/JAML/component.md#standalone-application-root); for embedded apps, preserve the [explicit host boundary](../references/JAML/component.md#embedded-application-hosts).
6. For galleries, retain complete legible examples. Keep small data inline, load large/shared datasets through documented data contracts, and extract real repetition without hiding every example behind a generic registry.
7. Follow [Validate](validate.md). Correct real errors; retain valid code when a diagnostic is an evidenced analyzer limitation.

When implementation exposes a meaningful reusable addition, follow [Upstream candidates](upstream-candidates.md) and retain its recommendation and approval status in the existing report or final handoff.

Done: requested behavior is implemented, selected capabilities and extensions have clear ownership, application theme conventions are applied, and verification results distinguish static from live evidence. Reusable additions have a concise contract and an example or meaningful test.
