# Registry contracts to inspect

Use the rows relevant to the requested registry. They guide source inspection, not a shared runtime shape or proposed field list. Confirm public identities, aliases, registration/import requirements and version availability through the target's current mechanisms.

| Family                                  | Distinctions that change selection or composition                                                                                                                                                                                                       |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Behavior plugins                        | Accepted host, activation/readiness, arguments, state ownership, event/subscription lifetime, interaction conflicts and disposal. Separate an initial effect from later listeners.                                                                      |
| Style plugins                           | Visual effect versus layout/behavior ownership; roles/tokens, inheritance, selector scope, precedence, responsive constraints and any lifecycle effects. Preserve geometry and scrolling owned by the layout.                                           |
| Framework or independently packaged CCs | Public inputs versus internal/default data, aliases and mutation ownership, effective root/variant contracts, dimensions, dependencies, interactions and intrinsic semantic domains. Preserve existing legacy interfaces until migration is authorized. |
| Usages                                  | Locate how the registered usage is looked up, applied and parameterized; inspect target compatibility, composition order and ownership of any produced state or effects. Do not infer these from its name.                                              |
| Suffixes                                | Inspect dispatch/matching, accepted operand/input, transformation or side effect, chaining/order and invalid-input behavior. Preserve the actual parser and registration contract.                                                                      |
| Builders                                | Inputs, produced structure, host/region responsibility, precedence/merge rules and supported extension points. Establish whether execution is pure construction or owns runtime effects.                                                                |
| Other registry extensions               | Discover the registration and consumer contract first. Record the distinct responsibility and its dependencies; do not force it into a plugin or CC shape.                                                                                              |

Selection guidance should connect a user intent to suitable owners across families. Prefer established composition when it fits; explain alternatives and legitimate fallback when requirements exceed the available contract. Missing metadata is uncertainty, not evidence that a capability is absent.

Independent packages retain their own identity, authoring source and discovery boundary. A supported workspace index or package artifact may expose only part of a contract. Keep richer curated knowledge with its current owner when the pipeline cannot carry it; report a proposed extension separately instead of claiming automatic ingestion into the framework catalog.

Keep domain overlays separate when they merely map business terms or examples onto reusable capabilities. Preserve domain restrictions that the implementation genuinely enforces, even when shared instructions are translated or generalized.
