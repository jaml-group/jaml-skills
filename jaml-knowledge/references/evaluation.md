# When comparing knowledge approaches

Use this only for an authorized experiment or a demonstrated selection/composition failure that needs comparison. Routine updates use focused source, resource and behavior checks.

Freeze the tasks, source/runtime baseline, acceptable choices, rejection reasons and scoring rubric before observing answers. Compare current evidence, freshness-corrected evidence and enriched evidence when this separates maintenance repair from added design knowledge. Use matched fresh contexts and model/settings, and keep prior packets/results immutable; corrections create a new identified condition.

Include fit, near-miss, missing-prerequisite and legitimate no-fit cases. Assess valid selection, composition prerequisites, contract violations, unsupported claims and justified fallback. Keep business-domain examples from becoming universal eligibility gates. Measure tokens or cost only when actual counters are available.

Report scope, confounders and untested contracts. A small pilot supports a bounded conclusion, not a whole-registry migration or a promised reproduction of published benchmark gains. Keep private implementation evidence and experiment records outside public skill resources.
